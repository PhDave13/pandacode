# Chats, connections, a design canvas and a skills library

## New

- **Chats without a project.** **New chat** starts a conversation that isn't tied to a codebase. Each chat gets its own folder under `~/PandaCode Chats`, chats are listed in their own Chats section, and project-only controls are hidden. **Move to project…** moves a chat into a project before it gets going.
- **Named connections for each agent.** Add "Claude Work" and "Claude Personal", or two Pi profiles. Each connection has its own executable, arguments, environment and config folder, and secret values are kept in the system keychain. Choose a connection per task in the model picker, and tasks keep theirs.
- **Design canvas.** Agents can create HTML artboards. You see them in the inspector's Design tab, pan and zoom around them, click an element to comment on it, and send the comments back to the agent. Artboards are files in `.pandacode/design`, so they show up in diffs and reviews.
- **Skills & rules library.** Import a skill or rule from a folder or a GitHub repository, then turn it on for each agent, either globally or for a project. The library shows which agent has what, spots edited or unmanaged copies, and scans for secrets or approval-bypass instructions before anything is turned on. It never overwrites files it didn't write.
- **Jujutsu.** Jujutsu (jj) repositories get their own Changes panel: change ID, description, bookmarks, changed files, diffs, Describe, New, Commit and the log. Repositories that also use Git show a jj chip.
- **Capabilities & cache.** Settings → Tools & add-ons lists each agent's commands, MCP servers, hooks and skills side by side, without exposing secrets. It also shows how PandaCode's instructions are cached for each agent, with the cache tokens the agent reported.
- **Workflow recipes.** Save multi-step routines as recipes, such as review, check, summarise and wait for approval. A dry run shows what each agent can do natively and what needs a fallback. Running a recipe queues its steps as ordinary messages. Open recipes from the `+` menu.
- **GitHub Copilot CLI** as an agent. Thanks @238SAMIxD (#73).
- **Workspace search.** The inspector has an activity bar and a Search tab with find-in-files results. Thanks @SakithaSamarathunga33 (#72).
- **Project checks after turns** (off by default). When an agent finishes cleanly, PandaCode runs the project's own test or check command. If it fails, one editable fix message is queued; it never loops. Thanks @matkarimov099 (#68).
- **Code search for agents.** If `codedb` is installed, agents get a fast, read-only code search tool, with codedb's telemetry and background daemon turned off. Thanks @matkarimov099 (#65).
- **New task from a project heading.** Hover over or focus a project in the sidebar to start a task there. Thanks @jojomensah89 (#76).
- **Intel Macs.** A native `PandaCode-macOS-x64.dmg` is published with automatic updates, and `npx pandacode` installs it.

## GitHub view

- **Keyboard navigation works everywhere.** The arrow keys move through workflow runs as well as pull requests and issues, and Enter opens the focused row.
- **Run details go deeper.** Expanding a run shows each job's steps with durations, the job's summary and earlier attempts.
- **Check workflow files** asks an agent to find invalid YAML, unknown runner labels and broken `uses:` references.

## Fixes

- **Node from fnm, nvm, mise, asdf or nvm-windows is found,** so agents installed with npm under a version manager work when PandaCode starts from the Dock.
- **Pi installed with the pi.dev installer works on Windows.**
- **The project picker no longer closes as it opens** right after a new task is created.
- **A board task you open while PandaCode is still starting stays open.**

## Known limitations

- Jujutsu support, codedb search and Copilot have been tested against recorded output only, not live installs.
- The Intel macOS build is new and hasn't been tried on a real Intel Mac yet.
- The design canvas runs no scripts inside artboards, so interactive prototypes appear static.
